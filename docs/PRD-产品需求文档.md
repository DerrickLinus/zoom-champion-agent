## **一、项目概述**

### **1\.1 项目背景**

南京市红山森林动物园是国内少数坚持“动物福利优先”理念的城市动物园——率先取消动物表演、拒绝付费投喂、以“动物为本”改造场馆。园区占地1026亩，森林覆盖率超85%，拥有270多种、3500余只野生动物，2024年全年接待游客797万人次，其中约六成为20\-30岁的年轻人，超八成来自南京以外。

然而，红山也面临着传统优质景区的共同困境：过去靠一位饲养员带一群游客讲一小时的“人力密集型”服务模式，在客流成倍增长后难以为继。红山有丰富的故事资产——多年公众号推文、饲养员日常记录、场馆讲解词、动物福利科普——但散落各处，游客能看到动物，却听不到“红山的方式”。

### **1\.2 产品愿景**

> 打造一个“有温度的智能游伴”——以小程序为初期载体，以具身智能硬件为远期延伸，让红山十年散落的故事跟着每一位游客走。产品内核坚持红山的价值观：“最好的观赏是不打扰，是让生命回归本真”。
> 
> 

### **1\.3 产品形态演进路径**

|阶段|形态|核心功能|目标|
|---|---|---|---|

\| **Phase 1** \| 微信小程序 \| 动态路线规划 \+ 多模态讲解 \+ 盲盒动物形象 \+ 成长体系 \| 验证核心体验，积累用户数据 \|

\| **Phase 2** \| 小程序迭代 \| 多智能体架构全面上线 \+ 实时动态调整 \+ 社交分享 \| 提升智能化程度和用户粘性 \|

\| **Phase 3** \| 硬件延展 \| Agent能力嵌入毛绒玩具/便携讲解器/AR眼镜 \| 让内容资产走出园门 \|

### **1\.4 目标用户**

\- **核心用户**：18\-35岁年轻游客（占红山现有游客约六成），追求个性化体验、愿意为有温度的内容付费。

\- **次核心用户**：带娃家庭（需要亲子友好的路线和讲解）、外地游客（需要高效的游览规划）。

\- **潜在用户**：无法亲临现场的远程用户（通过硬件产品听“今日红山的故事”）。

## **二、核心功能模块**

### **2\.1 模块一：盲盒动物形象（Onboarding 与情感联结）****  ****P2**

**功能描述**：用户首次进入小程序时，通过一组趣味问答生成专属的动物形象，建立情感联结。

**交互流程**：

1. 用户进入小程序，首先看到红山风格的欢迎动画。

2. 回答5\-8个抽象趣味问题（非敏感信息采集），例如：

    - “你更喜欢哪种颜色？”（森林绿 / 日落橙 / 星空蓝 / 晨雾灰）

    - “你最喜欢哪个季节？”（春天万物复苏 / 夏天热烈奔放 / 秋天静谧深沉 / 冬天纯净安宁）

    - “你更向往哪种自然景观？”（茂密雨林 / 辽阔草原 / 幽静山谷 / 浩瀚沙漠）

    - “周末你更愿意？”（探索新地方 / 窝着放空 / 和朋友相聚 / 独自散步）

3. 后台根据问题组合映射到预设的动物形象库（如：杜杜式白面僧面猴、考拉式慵懒派、长臂猿式自由魂、狼群式团队型等）。

4. 生成专属动物形象卡片，附带一句该动物的“性格签名”和红山小知识。

**技术实现**：

- 预设12\-16种动物形象，每种对应一组问题答案的组合规则。

- 动物形象数据包含：名称、性格标签、对应红山真实动物故事、形象插画。

- 形象数据存储于用户画像中，作为后续个性化推荐的基础。

**伦理约束**：不采集任何可识别个人身份的生物特征或身份信息；问题设计避开年龄、性别等敏感维度。

### **2\.2 模块二：游前动态路线规划****  ****P0**

**功能描述**：根据游客的多维度需求，生成高度定制的游园路线。

**输入维度**（用户可自由组合）：

- 可用时间（1小时 / 2小时 / 半天 / 全天）

- 体力状态（轻松 / 适中 / 挑战）

- 怕不怕晒（是 / 否 → 影响路线中遮阴路径的权重）

- 想不想爬山（是 / 否 → 红山依山而建，部分场馆需要爬坡）

- 带没带娃（是 / 否 → 影响场馆推荐和节奏建议）

- 想看哪类动物（灵长类 / 猫科 / 鸟类 / 本土物种 / 随缘）

- 当天卡路里预算（可选 → 推荐相应运动量的路线）

- 特殊需求（轮椅通行 / 婴儿车 / 偏好某些场馆/避开某些场馆等）

**输出内容**：

- 建议游览时长和最佳开始时间。

- 场馆访问顺序（最优路径，减少折返）。

- 每个场馆的预计停留时间。

- 途经点的休息区 / 餐饮点推荐。

- 路线总步行距离和预估卡路里消耗。

- 个性化推荐理由（如：“根据你‘不想爬山’的偏好，我们为你规划了一条以冈瓦纳、本土区为主的平缓路线”）。

**个性化适配示例**（呼应产品目标）：

- 给年轻人：“推荐从冈瓦纳开始——杜杜最活跃的时段是上午9\-10点，此时光线最佳，出片率最高”。

- 给带娃家长：“亚洲灵长馆的长臂猿一家上午比较活跃，建议先去；儿童乐园旁的休息区有遮阳伞，适合中途休整”。





### **2\.3 模块三：游中动态调整（管理预期 \+ 调整节奏）****P0**

**功能描述**：游览过程中，根据实时变化动态调整计划，真正做到“管理预期”。

**动态调整触发条件**：

|触发类型|具体场景|系统响应|
|---|---|---|

\| **用户主动调整** \| “走累了，想歇一会儿” \| 推荐最近的休息区 / 咖啡厅，调整后续路线缩短 \|

\| \| “不想玩了，想提前结束” \| 推荐最优离园路线，途经未打卡点快速浏览建议 \|

\| \| “这个馆太喜欢了，想多待会儿” \| 重新计算后续路线，压缩或跳过部分点位 \|

\| \| “肚子饿了” \| 推荐就近餐饮点，调整用餐后的路线 \|

\| **园区实时数据** \| 某场馆人流量过大 \| 主动建议规避：“xx馆当前排队需30分钟，建议先逛旁边的xx馆” \|

\| \| 某区域突发拥堵 \| 重新规划绕行路线 \|

\| **动物活跃度** \| 某动物当前正活跃 \| 主动推荐：“长臂猿此刻正在鸣叫，建议现在前往亚洲灵长馆” \|

\| \| 某动物正在休息 \| 温馨提示：“xx正在午休，建议稍后再来或先逛其他场馆” \|

**技术实现**：

- 园区实时客流数据接入（红山已有“智慧红山数智中心”，可对接客流统计和热点监控数据）。

- 动物活跃度：基于饲养员记录 \+ 历史行为模式（如长臂猿上午较活跃）\+ 物联网传感器（如有）。

- 用户实时位置通过小程序GPS获取。

- 支持多轮对话式调整：支持自然语言交互，局部修改无需重新规划全程。

### **2\.4 模块四：多模态讲解（三种触发方式）****P1**

优先实现讲解，再实现多模态。

**功能描述**：支持三种讲解触发方式，覆盖不同场景和用户偏好。

|触发方式|适用场景|技术方案|
|---|---|---|

\| **方式一：LBS自动触发** \| 用户进入场馆地理围栏，自动推送 \| 微信小程序 GPS \+ 蓝牙 iBeacon 辅助定位 \|

\| **方式二：用户手动点击** \| 不愿开定位 / 提前做功课 / 游后回顾 \| 小程序内场馆列表 / 地图标记点 \|

\| **方式三：硬件自动触发** \| 儿童或不掏手机场景（Phase 3） \| 硬件传感器检测到有人经过时触发 \|

**讲解内容特色**（区别于“百科腔”）：

- 以故事为载体，而非知识点堆砌。

- 保留红山动物福利立场，传递“不打扰”的观赏理念。

- 同一动物提供不同版本的讲解（如长臂猿：给年轻人讲“身披披的壮年”，给带娃家长讲家庭故事）。

- 拒绝商业化诱导。

### **2\.5 模块五：成长体系与内容资产走出园门****  /奖励机制。**

**功能描述**：通过游戏化的成长体系，激励用户深度参与，并为硬件延展铺路。

**成长值获取方式**：

- 完成游前路线规划并开始游览 → \+10

- 每参观一个场馆并收听讲解 → \+5

- 完成当日全部规划路线 → \+20

- 分享动物形象卡片到社交平台 → \+5

- 参与园区互动（如打卡点拍照） → \+5

- 连续使用（每日签到） → \+2/日

**动物形象成长**：

- 成长值累积到一定阈值（如100、300、500），用户的专属动物形象发生视觉变化（幼年→成年→壮年）。

- 不同成长阶段解锁不同的“动物故事”——红山真实动物的成长记录。

- 成长值达到特定里程碑，解锁限定版动物形象皮肤或徽章。

**硬件兑换机制（Phase 3）** ：

\- 成长值达到一定积分（如500分），获得“红山游伴”毛绒玩具的**购买资格**（非免费赠送，避免滥用）。

- 毛绒玩具内置Agent能力：按下即可播放“今日红山的故事”——每日更新的红山新鲜事、动物趣闻。

**核心价值**：让内容资产走出园门——即使不在红山，也能通过硬件听到红山的声音。

**设计原则**：成长体系服务于“深度体验”而非“刷分”，不鼓励单纯为了积分而打卡。

## **三、Multi\-Agent 架构设计**

### **3\.1 架构总览**

采用 **Orchestrator（编排层）\+ 专业Agent（执行层）** 的多智能体协同架构。Orchestrator统一调度各专业Agent，通过工作流（Workflow）协同完成复杂任务。

```Plain Text
┌─────────────────────────────────────────────────────────────────┐
│                        接入层                                   │
│              小程序前端 / 语音入口 / 拍照入口                    │
├─────────────────────────────────────────────────────────────────┤
│                      Orchestrator（编排层）                     │
│          LangGraph / 自研工作流引擎 + Session管理               │
├─────────────────────────────────────────────────────────────────┤
│                        Agent 层                                 │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐          │
│  │ Intent   │ │Profile   │ │Route     │ │Dynamic   │          │
│  │ Agent    │ │Agent     │ │Agent     │ │Adjust    │          │
│  │意图识别   │ │用户画像   │ │路线规划   │ │动态调整   │          │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘          │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐          │
│  │Content   │ │Multi-    │ │Animal    │ │Growth    │          │
│  │Agent     │ │Modal     │ │Active    │ │Agent     │          │
│  │内容生成   │ │Agent     │ │Agent     │ │成长体系   │          │
│  │          │ │多模态处理 │ │动物活跃度 │ │          │          │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘          │
├─────────────────────────────────────────────────────────────────┤
│                      服务层 / 外部 API                          │
│  通义千问/Qwen-VL │ 高德地图 │ 园区运营数据 │ 向量数据库       │
├─────────────────────────────────────────────────────────────────┤
│                       数据存储层                                │
│  用户数据 │ 内容资产（导游词/故事/科普） │ 园区数据            │
```

### **3\.2 各Agent职责说明**

|Agent|职责|输入|输出|
|---|---|---|---|

\| **Intent Agent（意图识别）** \| 将用户的自然语言/语音/图像转化为结构化意图 \| 用户输入（文本/语音/图像） \| 意图结构化数据（时长、偏好、约束等） \|

\| **Profile Agent（用户画像）** \| 管理和更新用户动态画像 \| 用户行为历史、动物形象、成长值 \| 个性化偏好向量 \|

\| **Route Agent（路线规划）** \| 在多重约束下生成最优游览路线 \| 意图数据 \+ 画像 \+ 园区实时数据 \| 路线方案（含时间、顺序、推荐理由） \|

\| **Dynamic Adjust Agent（动态调整）** \| 响应游览中的变化，实时调整计划 \| 用户新输入 \+ 位置变化 \+ 实时数据 \| 更新后的路线方案 \|

\| **Content Agent（内容生成）** \| 生成个性化讲解内容 \| 用户画像 \+ 场馆信息 \+ 内容资产库 \| 定制化讲解文本/音频 \|

\| **Multi\-modal Agent（多模态处理）** \| 处理语音/拍照/文字三种输入 \| 语音流 / 图像 / 文本 \| 识别结果 \+ 结构化数据 \|

\| **Animal Active Agent（动物活跃度）** \| 预测和推送动物活跃信息 \| 历史行为数据 \+ 实时传感器 \| 活跃度评分 \+ 推荐时机 \|

\| **Growth Agent（成长体系）** \| 管理成长值和动物形象进化 \| 用户行为事件 \| 成长值变更 \+ 形象更新 \|

### **3\.3 技术选型建议**

\- **编排框架**：LangGraph（支持状态化多智能体工作流，已有成熟的旅游规划案例）或 HelloAgents（轻量化文旅多智能体框架）。

\- **基础模型**：通义千问 Qwen\-Long / Qwen3\-Max（文本生成与推理）、Qwen\-VL（图像理解）、FunASR（语音识别）。

\- **向量数据库**：Milvus（存储和检索红山内容资产）。

\- **地图服务**：高德地图API（园区地图、路径规划、POI检索）。

### **3\.4 Agent间协作示例（场景说明）**

**场景：用户说“我带着3岁娃，想逛2小时，不想爬山”**

1\. **Intent Agent** 解析意图：\{时长:2h, 人员:成人\+3岁儿童, 约束:不爬山\}

2\. **Profile Agent** 调取用户画像（如有历史数据）：\{动物形象:考拉, 偏好:慢节奏\}

3\. **Route Agent** 综合生成路线：避开高差大的狼馆和猩猩馆，优先推荐本土区、冈瓦纳、灵长馆等平缓场馆。

4\. **Content Agent** 为带娃场景定制讲解：长臂猿“秋实”的成长故事（适合儿童听的版本）。

5\. **Animal Active Agent** 附加信息：“长臂猿一家上午比较活跃，建议先去亚洲灵长馆”。

6\. **Orchestrator** 整合输出完整的个性化方案。

## **四、数据与内容资产**

### **4\.1 场景数据（假设园区方可提供）**

- 部分园区运营数据（客流、场馆信息等）。

- 园区导游词（各场馆标准讲解内容）。

- 硬件方向的国内试用点位支持。

### **4\.2 需要自建的内容资产**

\- **场馆元数据**：位置、坡度、遮阴率、容纳人数、无障碍设施。

\- **动物行为数据**：各动物的活跃时段规律（基于饲养员记录和观察）。

\- **讲解内容库**：在导游词基础上，扩展为故事化、多版本的讲解内容。

\- **动物形象库**：用于盲盒动物形象的插画、性格标签、故事背景。

### **4\.3 内容生成原则**

\- **保留红山动物福利立场**：讲解中强调“动物是主人，游客是客人”，传递“不打扰”的观赏理念。

\- **拒绝百科腔**：以故事和情感打动，而非知识点堆砌。

\- **拒绝商业化诱导**：不主动推荐付费项目，不进行商业转化引导。

\- **同一内容多版本适配**：同一动物故事，为不同人群（年轻人、亲子、专业爱好者）提供不同讲述角度。

## **五、硬件延展规划（Phase 3）**

### **5\.1 硬件形态选项**

|形态|适用场景|技术要点|参考案例|
|---|---|---|---|

\| **毛绒玩具** \| 儿童陪伴、居家听故事 \| 语音合成 \+ 按压触发 \+ 每日内容更新 \| 京东AI毛绒玩具（能听会说懂情绪） \|

\| **便携讲解器** \| 园内游览（不想掏手机） \| GPS定位 \+ 自动触发讲解 \+ 轻量化 \| 传统景区讲解器 \+ AI能力 \|

\| **AR眼镜** \| 沉浸式体验 \| 视觉识别 \+ 虚实结合讲解 \| 需较高成本，适合高阶体验 \|

\| **动物形象挂件/胸针** \| 轻量化随身设备 \| 按压对话 \+ 游戏化交互 \| 低成本、高传播性 \|

### **5\.2 毛绒玩具方案（首选硬件方向）**

**产品定位**：让“红山的温度”走出园门——用户在家按下毛绒玩具，就能听到今日红山的故事。

**核心功能**：

- 每日更新内容：“今天杜杜做了什么？”、“长臂猿秋实的新动态”。

- 按压触发语音播放（简单易用，适合儿童和老人）。

- 与小程序成长体系联动：玩具可识别用户身份（通过NFC或扫码绑定），同步成长值。

**技术方案（MVP低成本验证）**：

- 方案A（推荐初期）：玩具内无智能芯片，通过扫描玩具上的二维码跳转小程序播放对应内容，成本极低，适合验证需求。

- 方案B（远期）：内置低功耗语音合成芯片 \+ Wi\-Fi/蓝牙模块，实时接收每日更新的音频内容。

## **六、伦理与合规**

严格遵循以下伦理原则：

1\. **不采集游客生物特征与身份信息**：不使用人脸识别、指纹等生物特征；不强制收集姓名、身份证等身份信息。

2\. **儿童年龄输入须监护人知情且本地处理**：涉及儿童的输入（如“带娃”选项），需有监护人知情同意提示；相关数据本地处理，不上传云端。

3\. **内容生成保留红山动物福利立场**：所有AI生成内容需经过审核，传递“尊重生命、敬畏自然”的价值观。

4\. **拒绝百科腔与商业化诱导**：内容以故事化、情感化为主，不主动推荐付费项目。

5\. **作品不构成官方推荐**：本作品不代表红山或文旅部门的官方推荐。
